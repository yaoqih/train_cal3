# 纯组内相对学习、状态分支与并行训练

当前算法为 `grouped-root-fork-relative-v2`，权重 schema 4。只在输入请求及其真实可达状态上做相对学习，无课程生成、教师搜索、行为克隆、固定参考模型、价值头或价值回归。旧权重、旧参数没有兼容分支。

物理层和调度层独立校验规则，策略在完整合法候选中选择一勾。推理时可显式选择学习引导搜索，搜索不参与训练，也不会自动接管逐勾策略。

## 一次训练迭代如何工作

1. 按打乱后的顺序选取16个训练请求组。每组8条轨迹，共128条。
2. 约30%的组从状态池中的同一个中间状态开始，其余从原始初态开始。池中没有该请求时从原始初态开始；没有按难度排序或人为小任务预热。
3. 冻结当前权重。CPU推进环境、枚举候选与编码图，GPU集中合批评分。每条轨迹独立抽样，直到完整、循环、死路或达到全局勾数上限。
4. 只在**同一请求、同一起始状态**的完整组内比较最终得分，产生相对优势。
5. 原始初态轨迹更新全部新动作；中间状态分支只更新第一勾，后续推演作为这一步的长期结果样本。
6. 整组打乱，每32条轨迹形成一个优化器更新块；默认2轮更新，最多8次优化器提交。KL超过阈值会提前停止。
7. 保存新的实际前缀到状态池，记录指标，按间隔验证和原子保存检查点。

分支近似回答：“站在同一个局面，这一勾走不同方向，最后哪个结果更好？”其续接前缀不参与反向传播，不把另一版本策略产生的旧动作当成本轮同策略动作。分支本身是当前策略重新采样，不复用旧动作概率或旧优势。

默认128条中通常约88条原始轨迹、40条分支轨迹。30%是**组数比例**，不是环境勾数比例；分支较短，日志分别统计两者的实际采样步数。分支首勾获得信用不意味着模型有显式Q头，网络仍然只输出动作分布。

## 总勾数与相对目标

令 `H` 为包含历史前缀的全局总勾数，`B` 为全局上限：

```text
完整：2 - H / (B + 1)
失败：-1 + 0.55 × 目标股道比例 + 0.45 × 合法有序后缀比例
         - 终止惩罚
终止惩罚：循环0.25，死路0.35，用尽预算0
```

完整结果严格优于失败结果；完整结果之间只比较总勾数。失败轨迹不再因提前结束获得“勾数更少”的奖励。局部进度用于探索，不能当作完整解；删除短失败奖励也不保证消除循环。

优势为组内中心化得分除以组内标准差，分母下限 `1e-3`，避免极小差异被放大。完全同分时优势为0，只有探索熵项。对同组所有得分减去共同的初态得分不会改变标准化优势，因此“比起点有进步”只作为独立诊断指标。

原始轨迹采用整条轨迹的终态信用，策略梯度按轨迹数平均；分支采用第一步信用。使用PPO式概率比率裁剪、探索熵、梯度裁剪和相对于**本批实际采样策略**的KL上限，没有长期冻结的参考模型。

训练默认 `B=64`，为试错保留空间；评估另外记录**完整且总勾数≤40**。40是业务质量目标，不是已知最优解证明。前缀20勾、续接25勾应记45勾，不满足40勾指标。各阶段不重置预算。

## 模型如何更准确地评价一勾

- 图包括股道、车辆、机车、目标位置节点，29维节点特征中包含已执行勾数、剩余总预算、容量、保护锚点、业务开放门槛与配额。
- 3层关系消息传递后，用双向GRU编码各股道及机车的当前有序车列，汇总回所属股道。
- 所有股道与机车之间进行2头全局注意力，传播远端容量和阻挡信息；不同请求图互相隔离。
- 每个候选显式观察来源、去向、搬动车段、首尾车、取走后暴露的车和放入处接触的车。
- 根据确定性转移得到动作后两条序列，使用带位置与数量的MLP汇总，编码“这一勾之后会怎样”。相同后序列在一次决策中只编码一份。这是位置相关的车序汇总，不是逐候选运行整张GNN或另一个GRU。
- 统一动作头输出每个合法 `(股道, get/put, 数量)` 的分数，输出维度随候选数变化。

对同一 `(股道, 类别)` 的每个候选分数减去该组合法数量选项数的对数，再做联合softmax。所有原始分数相同时，每个股道／类别组获得相同总概率，防止“可选数量多”天然占据采样。该分布也用于训练旧概率、贪心与搜索；它没有额外的硬动作过滤。

## 状态池与缓存的边界

状态池默认2048，按训练请求公平分配名额，再按勾深区间抽取，不只收集高进度状态。当前68个训练请求各最多30份，共2040份。相同布局与业务状态保留最短合法前缀；开放勾号的语义由调度层判重键保留。

池中的前缀从原始请求逐勾严格重放后才能采样，保护集合不重算、业务计数不清零。历史访问状态参与循环检测。验证与独立测试不写入池；保存和续训保留池、请求顺序及随机状态。

静态拓扑、目标边和保护锚点按请求预编译。精确决策缓存包含请求指纹、物理／业务契约、完整状态、精确勾号、业务上下文和预算。它与搜索中可归一化的状态去重键不同，不能跨不同预算复用概率。

每次采样批内，相同状态只做一次模型推理，但各轨迹仍独立抽样。模型更新后清空概率缓存。分支只保留首勾的训练图，后续图推理后可释放；原始轨迹保留采样图和旧概率供更新复用。

## CPU／GPU并行与优化器批次

CPU环境进程使用spawn，不持有CUDA模型。每个进程限制PyTorch线程数为1；同一请求组分配给同一进程，复用候选、图与前缀回放。就绪进程通过15毫秒合批窗口提交图，主进程在单张GPU上评分，不要求全体轨迹逐勾同步。

同一批采样期间权重冻结，收齐完整请求组后才更新。更新阶段不另外采集过期策略轨迹。多GPU和跨机器训练尚未实现。

三个批次参数有不同作用：

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| `inference-batch-size` | 64 | 一次GPU前向的最大决策图数 |
| `trajectory-batch-size` | 32 | 一次优化器更新包含的完整组轨迹数，向下取整到整组 |
| `minibatch-size` | 128 | 一次反向传播的决策图数，同一轨迹更新块内累积梯度 |

把显存分块从128改小不会自动增加优化器更新次数。BF16用于神经矩阵计算；消息、车段与序列聚合使用FP32，物理长度始终使用整数毫米。显式请求CUDA/BF16而设备不支持时直接报错；CPU运行必须指定 `--device cpu --precision float32`。

## 训练、续训和监控

从随机初始化开始：

```bash
python -m fzd_shunting train data/point_to_area/augmented \
  --rules configs/dispatch.json --iterations 10000 \
  --group-size 8 --groups-per-batch 16 --workers 8 \
  --device cuda --precision bfloat16 --inference-batch-size 64 \
  --trajectory-batch-size 32 --minibatch-size 128 \
  --branch-fraction 0.3 --state-pool-size 2048 \
  --update-epochs 2 --max-hooks 64 \
  --validate-every 25 --checkpoint-every 10 --output runs/new-policy.pt
```

续训当前权重，`iterations`为**额外增加**的次数：

```bash
python -m fzd_shunting train data/point_to_area/augmented \
  --rules configs/dispatch.json --iterations 10000 --max-hooks 64 \
  --resume runs/policy.pt --output runs/policy.pt
```

当前默认学习参数与随项目保存的schema-4权重一致。训练数据、规则、网络结构或学习签名改变会拒绝续训；奖励语义修改还须同步更新算法版本，不能用不同目标继续同一实验。恢复中断时裁掉未被检查点提交的日志，包括末尾不完整JSON。

输出包括：`policy.pt`（权重、优化器、随机状态、状态池）、`policy.metrics.json`（累计与验证指标）、`policy.history.jsonl`（逐轮相对得分、KL、熵、梯度、停止原因与耗时）。找到的完整训练方案另存为检查点中的记录，只作可行计划证据，不做监督训练标签。

重点检查完整率、40勾内完整率、成功总勾数、首次完整解出现时的累计环境决策数、根轨迹／分支的采样量与完成量、循环／死路比例和组内信号。`distinct_decision_states`去重统计实际决策状态；`sum_trajectory_unique_states`是逐轨迹计数之和，两者不能混用。旧一段历史日志的`unique_states`属于后者。

`environment_steps_per_second`包含本轮采样和更新，不含进程启动、周期验证和落盘。原始轨迹与分支的比例、网络结构和预算改变后，不能直接拿旧吞吐当作新版加速比。有效学习进展仍需看完整解；奖励上涨与GPU利用率都不能代替它。

## 验证和逐勾使用

```bash
python -m pytest -q
python scripts/benchmark_learning.py --configurations gpu8

# 单次最终测试：独立日期，贪心、8次采样、每请求120秒搜索、严格回放
python scripts/validate_learning.py --checkpoint runs/policy.pt \
  --workers 4 --max-hooks 40 --seconds 120 --output runs/v4-validation.json

python -m fzd_shunting next REQUEST.json --rules configs/dispatch.json \
  --checkpoint runs/policy.pt --max-hooks 40 --output runs/next-hook.json
```

性能脚本只使用训练分区，默认16组×8条、40勾上限、128决策分块、15毫秒合批，支持 `cpu gpu4 gpu8` 配置选择。它用相同网络与设置比较设备组合，不衡量学习效果。组数少于环境进程数时会有空闲进程，因此默认组数覆盖8个进程。独立测试结果不能再用于调参；日常模型选择使用14份验证请求。`evaluate`评估传入目录的所有有效请求，含训练请求时不能称作留出泛化率。

继续现场批次时传 `--current-state observed-snapshot.json`，同时保留原始请求。`next`只预测，不提交执行状态；预算耗尽时返回 `hook_budget` 和空动作，已完成时返回 `complete`。限时搜索使用同一权重的CPU前沿准备与GPU批量评分，时间、展开数、前沿和状态数均有上限；一批在途计算及进程退出可能略超过时间预算。部分计划通过回放不等于完整求解，有剪枝的搜索也不证明最优或无解。

本次短程训练的质量结果与已知边界见[验证记录](validation.md)。增加训练量可以扩大探索，但不能保证学会复杂请求；如果长期没有完整解，应先检查可解性、组内差异与信用分配，不用失败轨迹的局部进度替代验收。
