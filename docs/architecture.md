# 三层架构与当前契约

物理和业务规则负责确定可执行性；神经网络在合法候选中学习选择。权重承载调度偏好与长期结果估计，规则校验始终独立于权重。

## 三层职责

| 层 | 持有的事实 | 入口与职责 |
| --- | --- | --- |
| 物理环境 | `Yard`、车辆长度、`State` 中的车序、机车位置、车列、已执行勾数 | `Environment.transition` 校核物理条件，返回新状态、操作车段和路线 |
| 调度业务 | 原始请求目标、固定保护锚点、`Rules`、`BusinessContext` | `Dispatcher.candidates/prepare` 生成合法候选，`step` 提交，`GoalEvaluator` 验收终态 |
| 学习与规划 | GNN参数、训练优化器、搜索前沿 | `next_hook` 选下一勾，`rollout` 逐勾推演，`plan` 在预算内搜索 |

状态对象不可变；搜索分支携带各自的物理状态和业务上下文。模型不能直接改状态。执行时再次验证候选指纹和规则，状态、业务计数、事件按同一勾提交；过期候选、重复提交被拒绝。

## 物理转移

股道序列 `Q` 按北→南，机车序列 `T` 按近→远：

```text
Get(k): block = Q[:k];  Q = Q[k:];       T = T + block
Put(k): block = T[-k:]; T = T[:-k];      Q = block + Q
```

`k` 为正整数，一勾只改变一个股道和机车。检查到达、离开两种车列的实际毫米长度与数量，以及操作股道容量。库内外各自操作，进路占用体现库外挡车。清障必须另计动作，不隐式摘挂。

`Yard.load` 读取机车长度、牵引总长、辆数和进路模型配置。默认机车15米、总长193米、20辆。路由缓存只依赖起点端、占用集合、目标，不把与路线无关的完整车序及勾号纳入缓存键。

当前 `north-end-occupancy-v1` 检查北端接近和中间股道占用。`model_scope` 随计划输出，明确未建模的道岔组合、折返清尾、连续占用。没有微观空间参数时不能据此认证现场完整走行。替换路由器需要声明实际模型版本，不能把替代模型记为默认模型。

## 目标和保护

请求导入、数据增强、执行验收、查看器共享规范目标语义。每车目标为股道到允许位置集合的映射。当前实际车序必须存在严格递增的允许位置匹配；贪心为每车选择最早允许位置即可准确判断这一问题，无需枚举组合。

普通股道的位置域覆盖参考容量、候选车辆数与目标数字；逻辑位置不额外提供物理长度。修库内位置域固定为请求模式对应的5／7台位，实际终停长度另行检查。

保护车按**原始请求**识别：初态修库内、目标允许同股道和原台位。其逻辑锚点固定，且从最北保护车开始的原始后缀无法越过保护车抽取。存在保护车的库内只接受满足终态目标、顺序、容量的 Put；新放入但非保护的车辆仍可合法取出。无保护车的库内允许151.7米缓存。

目标验收首先检查物理状态与业务上下文，再检查所有车辆到位、顺序、终态容量及机车摘空；车辆丢失不能被误判为完成。

## 可组合业务规则

`constraints.py` 的纯函数接口为：

```python
constraint.before(dispatcher, state, context, action)
constraint.after(dispatcher, state, context, action, after, block)
new_context = constraint.advance(dispatcher, context, action)
errors = constraint.terminal(dispatcher, state, context)
```

内置开放勾号、初始保护／缓存、动作配额。配置示例：

```json
{
  "access_rules": [{
    "name": "大库开放", "lines": ["修1库内", "修1库外", "卸轮线"],
    "operations": ["get", "put"], "earliest_hook": 12
  }],
  "action_limits": [{
    "name": "存4交付", "lines": ["存4线"],
    "operations": ["put"], "max_actions": 1
  }]
}
```

第12勾开放表示1—11勾禁止相应操作；不会生成等待空勾。若其他区域不足以构造前置合法动作，可能没有可行计划。动作配额是整批共用上限；“最后一勾交存4”、先后依赖或“源线关闭”等不是配额自动推导出的规则，需要各自明确实现。

`BusinessContext` 当前保存命名动作计数，不复制车序。计数进入候选指纹、搜索判重、快照与图中的剩余配额。增加新业务类型时实现约束，并同步扩展必要的上下文序列化、判重和策略观察。约束用 `rule_id/version` 标识语义；修改语义须更新版本。不能宣称任意新需求都无需修改代码。

## 权重和会话契约

当前权重唯一格式为 schema 4，特征契约为 `container-boundary-after-order-budget-v3`。旧权重不加载。权重绑定 `yard_hash`、`rules_hash`、实际路由版本、目标语义、执行语义，同时校验图特征版本。请求不绑定为训练时那一批，因此同一权重可用于同规则下不同车数、目标集合、车序和机车状态。新规则需要重新训练匹配权重。

`Dispatcher.snapshot()` 包含 `state`、`business_context`、`contract_hash`、`scenario_hash`。恢复必须携带原始请求并校验两个指纹，保护集合不能从动态车序重新计算。快照校验可以发现结构／约束矛盾，不能证明外部填报的业务计数真实；可信接入应由执行日志维护上下文。

`next_hook` 不提交状态，只返回动作、车辆、进路、当前与预测快照。`step` 才是提交入口。离线 `replay` 对schema-2事件逐字段核对，计划继续段保留实际全局勾号。

## 图与候选评价

图有股道、车辆、机车、目标逻辑位置四种节点，29维节点特征、16种边关系；有向边表达南北连接、归属、车序、目标和保护初始锚点。静态拓扑与目标按请求预编译，动态填入车序、剩余配额、已执行勾数和剩余全局预算。预算使用固定尺度，初始40勾预算与64勾预算也可区分。

默认隐藏维96、3层关系消息传递。随后用双向GRU编码每条股道与机车的完整有序车列，再把车辆摘要汇总到容器。股道与机车之间增加2头全局注意力，让远端容器不受3层局部消息传播距离限制。不同请求的图、容器注意力与动作集合严格隔离。

每个动作先统一来源与去向：Get从股道到机车，Put从机车到股道。动作头观察10个96维摘要：全图、来源、去向、搬动车段均值、车段首尾、来源新暴露车、目的地接触车、来源操作后序列、目的地操作后序列；另有12维候选特征。输入为972维，经过96维隐藏层输出一个分数，不存在固定车辆数的动作输出维度。

操作后序列来自合法候选的确定性转移结果，用车辆嵌入加新位置／序列长度的MLP与均值汇总表达，不是每个候选再跑一次GRU。一次决策中相同后序列去重。首尾与接触边界另外显式保留，均值汇总不等于已证明无损表达任意组合关系。

动作分布对每个原始分数减去同一 `(股道, 类别)` 下合法数量选项数的对数。初始同分时各股道／类别的总概率相等，不让可选数量多的股道天然占据探索。其等价形式是组分数取log-mean-exp，再乘组内数量的条件softmax；采样、训练和搜索使用同一分布。

## 学习与搜索组件

| 组件 | 职责 | 生命周期 |
| --- | --- | --- |
| `policy/gnn.py` | 静态编码、动态图合批、纯策略评分 | 每请求编码器，每设备一份权重 |
| `decisions.py` | 精确候选与图缓存 | CPU进程内，含精确勾号、业务上下文和预算 |
| `sampling.py` | CPU环境、集中推理、真实前缀池与分支 | 跨训练迭代复用进程；概率缓存每批清空 |
| `learning.py` | 同请求同状态组内优势、优化器、验证与续训 | 整批采样冻结权重，收齐后更新 |
| `frontier.py` | 搜索前沿的CPU准备与GPU批量评分 | 每次搜索固定权重、独立进程池 |
| `feasibility.py` | 终态位置／数量与长度必要条件 | 加载请求和显式审计时检查 |

训练同时包含原始初态的完整轨迹与真实中间状态的分支。分支从原始请求回放前缀，保留保护锚点、业务配额、历史访问状态与总勾数；相对优势只在同状态的组内计算，分支只更新首个新动作。池不含验证或测试数据，完整方案记录不用于监督模仿。没有课程生成器、教师搜索、价值头或监督损失。

CPU进程准备候选与图，GPU只负责批量网络计算；同组分配到一个CPU进程以复用缓存，就绪进程无需等待最慢轨迹。每32条轨迹形成一次优化器更新，内部每128个决策图累积一次梯度。采样图与旧动作概率直接复用；分支后续图不存入训练记录。消息与序列聚合为FP32，神经矩阵支持BF16，物理毫米计算不变。

搜索调用同一网络批量排序前沿，保留部分股道／操作多样性，记录父指针，限制时间、展开数、前沿与已访问状态。找到完整解后保留它并继续尝试减少总勾数。判重携带业务上下文，在所有开放门槛之后才截断勾号差异；精确图与概率缓存仍使用真实勾号和预算。搜索有分支和前沿剪枝，不证明最优或无解。时间限制在批次之间检查，在途批计算与进程退出可能使实际耗时略超预算。

终态筛查先核验不可移动后缀，再检查车辆—逻辑位置—股道的容量流与允许拆分长度的松弛流。必要条件失败可排除请求，通过只表示尚未发现分配矛盾，不是完整调车证书。完整／部分计划都通过原始请求逐勾回放生成事件，保存后可再次独立回放核对。

训练路径、全局回报与实测范围见[学习说明](learning.md)和[验证记录](validation.md)。当前还没有缓存动作的全局可恢复证明、通用任务依赖系统或现场级连续空间模型。
